# AudioBridge 지연 정책

## 목표

**지연은 가능한 한 짧게, 여러 스피커의 소리는 같은 순간에.** 0ms는 물리적으로 불가능하다 —
소리는 캡처·Wi-Fi·출력 버퍼를 반드시 지난다. 그래서 AudioBridge는 세 층으로 맞춘다.

| 층 | 누가 | 무엇을 |
|---|---|---|
| 1. 공통 지연 (자동, 기본) | 앱이 스스로 | 끊기지 않는 가장 짧은 "소스 타임스탬프 → 소리" 시간을 모든 스피커가 공유 |
| 2. 스피커 소리 맞추기 | 사용자가 버튼 한 번 (기기를 붙여 놓고) | OS가 모르는 스피커 내부 처리 지연 차이를 마이크로 재서 보정 |
| 3. 수동 조정 | 사용자가 직접 | 공통 지연 40–2000ms 직접 선택, 기기별 추가 지연 0–300ms |

## 1. 자동 공통 지연

한 프레임이 제시간에 소리 나려면 `(도착까지 걸린 시간) + (출력 버퍼 깊이) ≤ 공통 지연`이어야 한다.

- 각 스피커(`DelayAdvisor`)는 패킷마다 `도착 시각 − (소스 타임스탬프 + 시계 오프셋)`을, 재생 루프에서 출력 버퍼 깊이를
  재고, **최근 60초 최댓값 + 15ms**를 10ms 단위로 올려 2초마다 소스에 `need`로 보고한다. Wi-Fi가 잠깐 멈추는
  꼬리까지 60초 창에 들어간다. Windows는 미리 채워 두는 출력 큐 대신 WASAPI 출력 지연(40ms)을 깊이로 쓴다.
- 소스(`DelayCoordinator`)는 스피커들의 `need` 중 **최댓값**을 공통 지연으로 정해 `delay`로 알린다.
  늘릴 때는 즉시(이미 늦은 프레임이 있었다는 뜻), 줄일 때는 20초 동안 계속 여유가 있을 때만 줄인다.
  바뀔 때마다 한 번 건너뛰거나 기다리므로(짧은 끊김) 자주 바꾸지 않는다.
- 측정 전에는 250ms로 시작한다. 혼자 들을 때(상대가 소스)는 자기 `need`로 스스로 정한다.

가상 시뮬레이션(`sim/sync`, 가정한 Wi-Fi·기기, 10분) 결과:

| 네트워크 | 자동이 고른 지연 | 녹음→소리 중앙값 | 지연 탓 끊김/분 | 싱크 오차 p99 |
|---|---:|---:|---:|---:|
| 좋은 5GHz 공유기 | 100–250ms | 114ms | 0.27 | 0.30ms |
| 보통 가정 Wi-Fi | 170–250ms | 194ms | 0.44 | 0.43ms |
| 혼잡·절전 Wi-Fi | 360–520ms | 374ms | 0.68 | 1.01ms |

지연의 바닥은 **가장 큰 스피커 출력 버퍼(수십 ms) + 캡처 묶음(≈20ms) + Wi-Fi 멈춤 꼬리**다.
패킷 손실로 인한 끊김(손실률에 비례)은 지연을 늘려도 막을 수 없다.

## 2. 스피커 소리 맞추기 (기기를 붙여 놓고)

시계 동기와 하드웨어 재생 헤드로 OS가 아는 경로는 샘플 단위로 맞지만, 스피커 내부 DSP·앰프처럼 OS가 모르는
지연은 기기마다 수 ms 다르다(시뮬 가정: 1.4–9.1ms → 보정 없이 싱크 오차 7.7ms).

- 스피커들을 소스 폰 옆에 **같은 거리로** 모아 두고 버튼을 누르면, 소스가 음악을 잠시 무음으로 바꾸고
  스피커마다 600ms 간격으로 3번씩 50ms 처프(1.5→6kHz)를 **음악과 같은 재생 경로로** 내게 한다(`sync tones`).
- 소스 폰 마이크 녹음(프레임마다 하드웨어 캡처 시각)에서 정합 필터로 도착 시각을 찾고(포물선 보간, 중앙값),
  가장 늦은 스피커에 맞춰 빠른 스피커의 보정값(`calUs`)을 정해 저장시킨다(`sync set`).
- 시뮬레이션(반사음·음색·잡음·거리 차 0–0.3ms 포함): 싱크 오차 p99 **0.41ms** (알고 있다고 가정한 정밀 보정 0.38ms).
- 스피커 간 거리가 다르면 그 차이(10cm ≈ 0.3ms)가 오차로 남는다. 맞춘 뒤 스피커를 옮겨도 전기적 지연 차이는 그대로라 유지된다.

## 3. 수동 조정

- **공통 지연 자동 끄기**: 40–2000ms(10ms 단위)를 직접 고른다. 소리가 흐르는 중에도 모든 스피커에 바로 적용된다.
- **이 기기 추가 지연**: 0–300ms. 공통 시각보다 이 기기만 더 늦춘다(앞당길 수는 없다 — 이미 지난 시각에 낼 수 없으므로).

## 구조적 한계

AudioPlaybackCapture로 다른 앱의 소리를 복제할 때, AudioBridge는 **그 앱이 소스 기기 자체 스피커로 내보내는
원음 경로를 지연시킬 권한이 없다.** 네트워크 스피커는 반드시 캡처·전송·재생 경로를 지나므로 소스 기기의 원음보다
늦다. 함께 들을 때는 소스 기기를 음소거하고 연결된 스피커만 쓰는 것이 가장 정확하다.

## 이전 정책 (v2.7–v2.8)

공통 지연을 600–2000ms(200ms 단위)로 고정하고, 두 기기의 음향 왕복으로 그 단계 하나를 고르는 방식이었다.
시뮬레이션에서 600ms에서도 싱크 오차 중앙값 8.3ms·분당 25회 끊김이 나와(원인: 타임스탬프 흔들림, 5ms 프레임 판단,
시계 동기 편향) v2.9에서 위 방식으로 바꿨다.
