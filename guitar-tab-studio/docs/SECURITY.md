# 보안 점검 기록 — 기타 탭 스튜디오

이 앱은 **로컬 서버 없이 `file://` 로 브라우저에서 직접 실행**되며, 백엔드가 없습니다.
그래서 서버측 공격면(인증·세션·SQL·SSRF 등)은 존재하지 않습니다.
아래는 이 구조에서 실제로 의미가 있는 항목만 점검한 결과입니다.

## v1.0.0 (2026-09-11)

| 항목 | 결과 |
|---|---|
| 코드에 하드코딩된 자격증명(API 키·토큰) | **없음.** 저장소 전체를 `sk-ant-`, `ghp_`, `github_pat_`, `AKIA` 패턴으로 스캔 — 검출 0건. AI 기능은 사용자가 직접 입력한 키만 쓴다. |
| API 키 저장 위치 | 브라우저 `localStorage`(이 기기 한정). 코드/패키지/릴리즈 어디에도 포함되지 않는다. 설정에서 칸을 비우고 저장하면 즉시 삭제된다. |
| API 키 전송 범위 | `api.anthropic.com` 한 곳뿐. 다른 도메인으로 보내는 코드 경로가 없다. |
| 외부로 나가는 네트워크 요청 | 딱 둘. ① 업데이트 확인 `api.github.com` (읽기 전용 공개 API, 인증 없음) ② 사용자가 AI 다듬기를 눌렀을 때의 `api.anthropic.com`. 그 외에는 오프라인 동작. |
| AI에 전송되는 데이터 | 오디오·파일·개인정보는 **전송하지 않는다.** 사용자가 만든 채보에서 뽑은 음악적 요약(마디 수, 음표 밀도, 코드 진행, BPM, 조성)만 보낸다. |
| 제3자 스크립트 / CDN | **0개.** 모든 코드가 저장소 안에 있고 외부 스크립트를 불러오지 않는다. 공급망 침해 경로 자체가 없다. |
| XSS | 사용자 입력(제목·연주자·메모)은 전부 `textContent` / `input.value` 로만 다룬다. `innerHTML` 을 쓰는 3곳(업데이트 모달)은 모두 `esc()` 로 HTML 이스케이프한 뒤 삽입한다. GitHub 릴리즈 본문(외부 문자열)도 같은 경로로 이스케이프된다. |
| 화면 캡처 권한 | `getDisplayMedia` 로 받은 **영상 트랙은 즉시 `stop()`** 하고 오디오만 녹음한다. 화면 픽셀을 읽거나 저장하지 않는다. 녹음본은 메모리에만 있고 기기 밖으로 나가지 않는다. |
| 마이크 | 요청하지 않는다. |
| 저장 데이터 | 악보는 IndexedDB(이 기기)에만. 설정에서 "저장된 악보 전부 지우기"로 완전 삭제 가능. |
| 업로드 파일 처리 | `decodeAudioData` 로만 해석한다. 파일 내용을 실행하거나 평가(`eval`)하지 않는다. 15분 초과 파일은 메모리 보호를 위해 거부한다. |
| 릴리즈 산출물 무결성 | 업데이트는 자동 설치되지 않는다. 변경 내역을 보여주고 사용자가 직접 GitHub 릴리즈에서 받아 덮어쓴다(무단 원격 코드 실행 경로 없음). |
| 의존성 취약점 | 런타임 의존성 0개 → 해당 없음. |

### 이번 버전에서 개선한 취약점
첫 릴리즈이므로 **이전 버전에서 고친 취약점은 없습니다.** 대신 설계 단계에서 아래를 미리 차단했습니다.

1. **키 유출 경로 차단** — AI 기능을 넣으면서 키를 코드/설정 파일에 두지 않고 `localStorage`로 분리, 전송 대상 도메인을 한 곳으로 고정.
2. **외부 문자열의 XSS 차단** — GitHub 릴리즈 본문을 그대로 `innerHTML` 에 넣지 않고 이스케이프 후 삽입.
3. **과잉 권한 차단** — 탭 캡처가 화면 영상까지 받을 수 있는 점을 고려해, 스트림 획득 즉시 영상 트랙을 종료하도록 구현.
4. **공급망 차단** — CDN·외부 스크립트를 한 개도 쓰지 않음(오프라인 구동 요구사항과 동일한 조치).

### 남아 있는 고려사항
- `file://` 로 여는 특성상 브라우저가 **오리진을 공유**할 수 있습니다. 같은 브라우저에서 신뢰할 수 없는 다른 로컬 HTML 파일을 열어 두지 마세요(API 키를 저장해 쓸 경우).
- AI 다듬기를 쓰면 곡 구조 요약이 Anthropic 서버로 전송됩니다. 그 자체가 싫다면 키를 넣지 않으면 됩니다(나머지 기능은 전부 동작).
