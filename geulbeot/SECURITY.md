# 보안 점검 기록

글벗은 **남이 만든 문서를 여는 앱**입니다. 문서는 신뢰할 수 없는 입력이고, 메신저나 다운로드로
들어옵니다. 그래서 이 문서는 "무엇을 막았는가"를 항목별로 적어 둡니다.

---

## 1. 문서는 기기 밖으로 나가지 않는다

| 항목 | 상태 |
|---|---|
| 문서 내용을 서버로 보내는 코드 | **없음.** 네트워크 호출은 `update/UpdateChecker.kt` 한 곳뿐입니다. |
| 분석·추적·광고 SDK | **없음.** 의존성은 AndroidX와 Compose뿐입니다. |
| 클라우드 백업으로 나가는 문서 내용 | **차단.** 아래 3번 참고. |
| PDF 변환·인쇄 | 전부 기기 안에서 처리합니다 (`android.graphics.pdf`, 안드로이드 인쇄 프레임워크). |

## 2. 권한을 최소로 가져간다

선언한 권한은 세 개입니다.

| 권한 | 왜 필요한가 |
|---|---|
| `INTERNET` | GitHub 공개 릴리즈 확인 |
| `ACCESS_NETWORK_STATE` | 네트워크가 없을 때 확인을 건너뛰기 위함 |
| `REQUEST_INSTALL_PACKAGES` | 사용자가 승인한 업데이트 설치 |

**저장소 권한(`READ_EXTERNAL_STORAGE`, `MANAGE_EXTERNAL_STORAGE`)은 선언하지 않습니다.**
파일은 SAF(Storage Access Framework)로만 접근하므로, 앱이 볼 수 있는 파일은 사용자가 시스템
파일 선택 창에서 직접 고른 것뿐입니다. 목록에서 문서를 지우면 그 파일의 지속 권한도 함께 반납합니다
(`DocumentStore.releasePermission`).

## 3. 개인정보가 파일과 백업에 새지 않게 한다

- **문서 메타데이터를 자동으로 채우지 않습니다.** 지은이·제목은 사용자가 문서 정보 창에서 직접 적은
  것만 저장됩니다. 기기 소유자 이름이나 계정이 문서에 들어가지 않습니다.
- **저장 파일의 시각 정보를 고정합니다.** `.hwp`의 복합 문서 디렉터리 타임스탬프는 0으로,
  `.hwpx`의 ZIP 항목 시각은 고정값으로 씁니다. 같은 문서를 두 번 저장하면 바이트가 같습니다
  (테스트 `saving twice produces identical bytes`로 확인).
- **최근 문서 목록을 클라우드 백업에서 제외했습니다.** 목록 항목은 파일 이름과 본문 앞부분 120자를
  담고 있어 그 자체가 문서 내용입니다. `backup_rules.xml`과 `data_extraction_rules.xml`은
  설정 파일 하나만 `<include>` 합니다. `<include>`가 하나라도 있으면 백업 대상은 **허용 목록**이
  되므로, 최근 문서 목록과 자동저장 폴더는 적을 필요도 없이 빠집니다.
- **자동저장은 앱 내부 저장소에만 씁니다.** 원본 파일은 사용자가 저장을 누를 때만 바뀝니다.

## 4. 악의적인 문서를 견딘다

| 공격 | 대응 | 확인 |
|---|---|---|
| **압축 폭탄** (작은 파일이 수 GB로 팽창) | 스트림당 256MB, `.hwpx` 전체 512MB 상한. 넘으면 사용자에게 설명하고 중단 | `SafetyLimitsTest` |
| **Zip Slip** (`../` 경로로 폴더 밖에 쓰기) | `/`·`\`로 시작하거나 `..`을 포함한 항목은 무시 | `SafetyLimitsTest` |
| **XXE** (XML 외부 엔티티로 기기 파일 읽기) | SAX 파서에서 doctype과 외부 엔티티를 모두 비활성화, 엔티티 해석기도 빈 값 반환 | `SafetyLimitsTest` |
| **손상된 레코드 크기** | 모든 레코드 크기를 남은 바이트와 대조, 초과 시 명확한 오류 | `RecordCodecTest` |
| **순환 섹터 체인** (복합 문서 무한 루프) | 방문한 섹터를 추적해 순환 발견 시 중단 | `CfbReader` |
| **범위 밖 섹터 참조** | 파일 크기와 대조 | `CfbReader` |
| **암호·DRM·배포용 문서** | **우회하지 않습니다.** 감지해서 열기를 거부하고 한글 PC판에서 해제하라고 안내 | `Hwp5RoundTripTest` |

## 5. 업데이트 경로

요구사항대로 GitHub 릴리즈 기반 자체 업데이트를 넣었습니다. 이 경로는 설치 파일을 다루므로
따로 점검했습니다.

- **토큰·자격 증명이 코드에 없습니다.** 공개 저장소의 공개 API(`api.github.com/repos/.../releases/latest`)만
  씁니다. 인증이 필요 없습니다.
- **HTTPS만 씁니다.** 리다이렉트를 직접 따라가면서 매 단계 프로토콜을 확인하고, HTTPS가 아니면
  중단합니다. `HttpURLConnection`은 프로토콜이 바뀌는 리다이렉트를 따라가지 않지만 그 사실을
  알려주지도 않기 때문에 직접 처리합니다.
- **다운로드 크기 상한 200MB.** `Content-Length`와 실제 수신량 양쪽을 검사합니다.
- **설치는 항상 사용자 승인 두 번.** 앱이 물어보고, 안드로이드가 다시 물어봅니다. 안드로이드는
  앱이 자기 코드를 임의로 교체하는 것을 허용하지 않으며, 그것이 옳습니다.
- **확인 실패가 앱 사용을 막지 않습니다.** 네트워크가 없거나 GitHub에 접근할 수 없으면 조용히
  넘어가고, 사용자가 직접 확인했을 때만 실패 사유를 보여 줍니다.

## 6. 파일 공유 경로

`FileProvider`가 노출하는 경로는 앱이 스스로 쓰는 세 곳뿐입니다 (`cache/exports`, `cache/updates`,
`files/documents`). 앱 저장소 루트를 노출하지 않습니다. 공유 시 부여되는 권한은 해당 URI 한 건에
대한 일시적 읽기 권한입니다. 내보낸 파일은 앱을 켤 때마다 정리합니다.

내보내기 파일 이름은 경로 구분자와 예약 문자를 걸러냅니다 (`DocumentStore.createExportFile`).

## 7. 빌드와 저장소

- `.gitignore`에 `*.jks`, `*.keystore`, `keystore.properties`, `local.properties`가 들어 있습니다.
- 배포용 압축(`./gradlew packageDistribution`)은 `checkNoSecrets` 작업을 먼저 실행합니다.
  서명 파일이나 자격 증명 파일이 하나라도 있으면 빌드를 실패시킵니다.
- 릴리즈 서명 설정은 `keystore.properties`가 있을 때만 구성됩니다. 없으면 서명 없이 빌드되며,
  **자리표시자 키조차 저장소에 들어가지 않습니다.**

## 이번 작업에서 개선한 취약점

1. **클라우드 백업으로 문서 내용이 나가던 문제** — 최근 문서 목록에 본문 앞부분이 들어 있는데
   백업 규칙이 이를 포함하고 있었습니다. 백업과 기기 이전 양쪽에서 제외했습니다.
2. **압축 해제에 상한이 없던 문제** — 작게 만든 악성 문서가 메모리를 고갈시킬 수 있었습니다.
   스트림당·아카이브당 상한을 넣고 테스트로 고정했습니다.
3. **그 백업 규칙 자체가 문법 오류였던 문제** — 1번의 수정이 형식상 잘못 쓰여 있었습니다.
   `<include>` 옆에 둔 `<exclude>`들이 허용 목록 밖의 경로를 가리켰고(오류), 존재하지 않는
   `cache` 도메인을 제외하려 했습니다. 규칙 파일이 유효하지 않으면 규칙이 의도대로 적용된다는
   보장이 없습니다. 릴리즈 빌드의 `lintVitalRelease`가 오류 11건으로 잡아냈고, `<include>`
   하나만 남겨 허용 목록으로 정리했습니다. **디버그 빌드만으로는 잡히지 않는 종류입니다.**

그 밖에 이번 작업에서 새로 발견된 취약점은 없습니다.
