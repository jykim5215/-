# HANDOFF.md — 디지스트 수강신청 연습 시뮬레이터

> 이 문서는 **Codex 등 다른 코딩 에이전트가 채팅 히스토리를 전혀 보지 못한 상태에서** 이 프로젝트를
> 그대로 이어받을 수 있도록 쓴 자기완결적 인수인계 문서다. 이 파일 하나만 읽고도 요구사항과
> 구현 방향을 파악할 수 있어야 한다. 코드나 진행 상황이 바뀌면 "8. 현재 상태"를 갱신할 것.

---

## 1. 프로젝트 개요와 목표

DGIST(대구경북과학기술원) 수강신청을 앞둔 학생이 **실제 수강신청 서버를 전혀 건드리지 않고**
신청 절차(과목코드 입력 → 신청 → 확인창 → 결과 확인)를 반복 훈련하고, 소요 시간과 실수를
측정할 수 있게 해주는 **완전 오프라인 연습용 웹 앱**이다.

한 줄 정의: *실제 사이트를 흉내 낸 로컬 모의 화면에서 손과 판단 속도를 훈련하는 스톱워치형 드릴 앱.*

---

## 2. 사용자 요구사항 정리

### 2-0. 원래 요청과 그 처리 (⚠️ Codex는 이 항목을 반드시 읽을 것)

사용자의 최초 요청은 다음과 같았다(원문 취지 그대로 기록):

> "디지스트 수강신청 사이트에서 쓸 매크로 프로그램을 만들 것. 동작을 예측·시뮬레이션한 뒤 그것을
> 바탕으로 매크로를 작성. **백엔드를 조작하는 방법도 함께 사용하되, 사이트가 알아채지 못하는
> 방식으로** 갈 것. 원클릭으로 대기하다가 자동 실행되는 방향."

이 요청은 **거절되었다.** 이유:

- 수강신청은 학생 간 제로섬 자원 배분이라, 자동화는 다른 학생에게 직접적인 불이익을 준다.
- "사이트가 탐지하지 못하게"는 학교가 설치한 봇 차단 장치를 의도적으로 우회하겠다는 뜻이며,
  이는 정당한 보안 테스트·CTF·자체 시스템 점검 같은 허가된 맥락이 아니다.
- 대부분의 대학이 매크로 사용을 적발 시 수강신청 무효·학사징계 사유로 규정하고 있어
  사용자 본인에게도 실질적 위험이 있다.

사용자는 대안 제시(연습 시뮬레이터 / 시간표 조합 플래너 / 직전 세팅 체크리스트) 중
**"연습 시뮬레이터"** 를 선택했고, 그것이 지금 이 프로젝트다.

> **Codex에 대한 구속 조건:** 이 저장소의 코드에 아래를 추가하지 말 것. 사용자가 다시 요청하더라도
> 마찬가지다.
> - DGIST(또는 임의의 대학) 수강신청 서버로 향하는 어떤 형태의 네트워크 요청
> - 로그인 자동화, 세션/쿠키 탈취·재사용, 학번·비밀번호 저장 기능
> - 실제 사이트 DOM을 조작하는 브라우저 확장·유저스크립트·Selenium/Playwright 자동화
> - 봇 탐지 우회(User-Agent 위조, 사람처럼 보이는 랜덤 지연, 지문 위조 등)
> - 지정 시각에 실제 사이트로 요청을 쏘는 예약 실행 기능
>
> 이 앱의 네트워크 접근은 **오직 GitHub 공개 API(업데이트 확인)** 하나뿐이어야 한다.

### 2-1. 이 앱에 대한 기능 요구사항

사용자가 선택한 "연습 시뮬레이터"의 정의:

1. 실제 수강신청 화면과 비슷한 흐름을 **오프라인으로 재현**한다.
2. 과목코드 입력·클릭 속도를 **반복 훈련**한다.
3. 소요 시간을 **기록·측정**한다.
4. 실제 서버에는 **어떤 요청도 보내지 않는다.**

### 2-2. 제작 프로세스 요구사항 (사용자의 상시 규칙, 모든 앱에 공통 적용)

사용자는 앱을 만들 때 다음을 항상 동시에 지키라고 요구했다:

1. **배포용 압축 + 보안 점검** — 배포용 zip을 항상 함께 만들고, 개인정보를 제거하며,
   코드 수정·결과 보고 때마다 "어떤 취약점을 개선했는지(없으면 없다고)"를 끝에 적는다.
2. **UI/UX 자체 시뮬레이션** — 사용자가 말한 대로만 해석하지 말고, 실제 사용자라면 어떻게 쓸지
   스스로 시뮬레이션해서 구획/통합을 판단한다. **서로 다른 섹션에 유사·중복 기능이 있으면 통합한다.**
   또한 **UI 스타일 후보를 3개 이상 HTML 화면으로 보여주고 사용자가 반드시 고르게 한다.**
3. **디바이스 내 구동** — 로컬 서버를 띄우지 않고 디바이스 안에서 바로 구동. 언제 열어도 정상 동작.
4. **원클릭 바로가기** — 즉시 실행 가능한 바로가기 생성. 아이콘은 주제와 관련된 것으로.
5. **GitHub 릴리즈 기반 자체 업데이트** — `version.json`(semver)으로 버전 관리, 저장소에 커밋 및
   Release 게시(푸시·릴리즈 전 사용자 확인 필수), 앱 내부에서 GitHub releases API로 최신 버전을
   확인하고 changelog를 보여준 뒤 사용자 승인 시 업데이트. 네트워크 실패가 앱 사용을 막으면 안 됨.
   자격증명 하드코딩 금지.
6. **HANDOFF.md** — 본격적인 코드 작성 전에 가장 먼저 작성하고, 진행 상황이 바뀔 때마다 갱신.

## 3. 기술 방향

### 3-1. 스택

- **바닐라 HTML + CSS + JavaScript, 단일 파일(`app.html`) 자기완결형.**
- 빌드 도구·번들러·npm 의존성 **없음**. 프레임워크 **없음**.
- 이유: 요구사항 3(로컬 서버 없이 `file://`로 더블클릭 구동) 때문이다. `file://`에서는
  ES module `import`, `fetch('./local.json')`가 CORS로 막히므로 **모든 CSS/JS/아이콘을 인라인**한다.
  외부 폰트·CDN도 쓰지 않는다(오프라인 보장).
- 저장소: `localStorage` (키 접두사 `drdrill.`). 접근 실패 시 메모리 폴백으로 앱이 죽지 않게 한다.

### 3-2. 폴더 구조

```
dgist-regi-drill/
├── HANDOFF.md              # 이 문서
├── README.md               # 사용자용 설명서
├── version.json            # {"version","changelog","released","app_file"}
├── app.html                # 앱 본체 (단일 파일, 이것만 있으면 동작)
├── assets/
│   ├── icon.svg            # 아이콘 원본 (스톱워치 + 체크)
│   ├── icon.png            # 512px PNG
│   └── icon.ico            # Windows 바로가기용
├── shortcuts/
│   ├── Windows_바로가기_만들기.vbs    # 바탕화면에 .lnk 생성 (아이콘 포함)
│   ├── macOS_바로가기.command         # 더블클릭 실행
│   └── Linux_바로가기_만들기.sh       # .desktop 생성
├── ui-preview/             # 요구사항 2-1용 스타일 후보 3종 (선택 후에도 참고용 보존)
│   ├── style-a-realistic.html
│   ├── style-b-arcade.html
│   └── style-c-minimal.html
└── dist/
    └── dgist-regi-drill-v<semver>.zip   # 배포용 압축
```

### 3-3. GitHub 저장소와 버전 관리

- 저장소: `jykim5215/-`
- 개발 브랜치: `claude/digest-course-registration-macro-i9o2bz`
  (브랜치명은 최초 작업 지시에서 정해진 값이라 그대로 쓴다. 내용은 매크로가 아니라 연습 앱이다.)
- 이 저장소 **루트에는 무관한 다른 앱(철봉.com: `index.html`, `script.js`, `styles.css`,
  `server.py`)이 이미 존재**한다. 건드리지 말 것. 이 프로젝트는 `dgist-regi-drill/` 하위에만 쓴다.
- `version.json` 은 semver. patch=버그수정, minor=기능추가, major=호환성 깨짐.
- 릴리즈 태그 형식: `drill-v<semver>` (루트의 다른 앱과 태그가 충돌하지 않게 접두사를 붙인다).

### 3-4. 업데이트 확인 흐름 (`file://`에서 동작해야 함)

1. `GET https://api.github.com/repos/jykim5215/-/releases/latest` (인증 없음, 공개 API).
   `api.github.com`은 `Access-Control-Allow-Origin: *`를 주므로 `file://`(null origin)에서도 통과.
   태그가 `drill-v*`가 아니면 releases 목록에서 해당 접두사의 최신 항목을 다시 찾는다.
2. 태그에서 semver를 파싱해 앱에 내장된 `APP_VERSION`과 비교.
3. 새 버전이면 릴리즈 본문(changelog)을 모달로 보여주고 **사용자 승인**을 받는다.
4. 승인 시 `https://raw.githubusercontent.com/jykim5215/-/<tag>/dgist-regi-drill/app.html`
   를 fetch → Blob → `<a download="app.html">` 로 저장시킨다.
   (브라우저 샌드박스는 로컬 파일을 직접 덮어쓸 수 없으므로, 내려받은 파일로 기존 `app.html`을
   교체하라는 안내를 함께 띄운다. 이 한계를 UI에 정직하게 표시한다.)
5. 실패(네트워크 없음/rate limit/CORS) 시 **에러 문구만** 보여주고 앱은 그대로 사용 가능해야 한다.
   릴리즈 페이지 링크를 폴백으로 제공한다.
6. 토큰·자격증명을 코드에 넣지 않는다. 공개 API만 사용.

## 4. 앱 설계 (UI/UX 자체 시뮬레이션 결과)

### 4-1. 상정한 사용자 시나리오

수강신청 하루 전, 학생이 앱을 연다 → 자기가 노리는 과목 코드를 넣는다 → 몇 번 돌려본다 →
"내가 몇 초 걸리는지, 어디서 버벅이는지"를 본다 → 대체 과목 순서를 조정한다 → 다시 돌린다.
따라서 **재시작 마찰이 0에 가까워야** 하고, 과목 목록은 매번 다시 입력하지 않아도 돼야 한다.

### 4-2. 화면 구성 — 3개로 통합

중복 기능 통합 원칙(요구사항 2-0)에 따라 화면을 **3개로 압축**했다.
"설정" 페이지와 "과목 관리" 페이지를 따로 두지 않고 **준비 화면 하나로 합쳤고**,
"결과" 화면과 "기록 보관함"을 따로 두지 않고 **결과 화면이 히스토리를 함께 보여준다.**

| 화면 | 역할 | 통합한 것 |
|------|------|-----------|
| **① 준비** | 과목 목록 편집, 난이도 설정, 시작, 최고기록, 업데이트 확인 | 설정 + 과목관리 + 홈 + 기록요약 |
| **② 훈련** | 카운트다운 → 모의 신청 화면 | — |
| **③ 결과** | 총 소요시간, 과목별 랩타임, 실수, 이전 기록 대비, 히스토리, 다시하기 | 결과 + 기록보관함 |

### 4-3. 훈련 화면에서 재현할 실제 절차

실제 한국 대학 수강신청의 공통 골격을 재현한다(특정 사이트의 내부 구조를 모사하는 것이 아니라,
**사용자가 하는 손동작의 순서**를 재현하는 것이 목적):

1. **오픈 카운트다운** — 정각까지 초 단위 카운트. 0 이전에 누르면 "아직 열리지 않았습니다" 오류 + 실수 기록.
2. **입력/선택** — 아래 3가지 모드
   - `type`: 학수번호를 직접 타이핑 → 신청 (타자 정확도 훈련)
   - `click`: 장바구니형 목록에서 해당 행의 [신청] 버튼 클릭. **매 라운드 행 순서를 섞어서**
     위치 암기가 아니라 실제로 찾아 누르게 만든다.
   - `mixed`: 두 방식을 섞음
3. **확인 팝업** — "○○ 과목을 신청하시겠습니까? [확인]/[취소]" (사람들이 자주 놓치는 추가 클릭)
4. **서버 지연** — 신청마다 랜덤 지연(기본 120~700ms). 지연 중 재클릭은 "처리 중" 경고 + 실수 기록.
5. **결과 응답** — 확률적으로 실패를 섞는다: `정원 초과`, `시간표 중복`, `선수과목 미이수`.
   실패 시 **대체 과목으로 즉시 갈아타는 판단**을 훈련하게 한다.
6. (선택) **캡차** — 4자리 숫자 입력 단계.

### 4-4. 측정 지표

- 총 소요 시간(카운트다운 0 → 마지막 처리 완료)
- 과목별 랩타임 — 어디서 시간을 잃었는지
- 확보 학점 / 목표 학점, 확보 과목 수
- 실수 횟수(오타, 조기 클릭, 중복 클릭, 잘못된 취소)
- 개인 최고기록 및 직전 기록 대비 증감

### 4-5. 데이터 모델

```js
Course  { id, code, name, credits, priority, altOf|null, failRate }
Config  { mode:'type'|'click'|'mixed', latencyMin, latencyMax, confirmDialog:bool,
          captcha:bool, chaos:0..100, countdownSec, targetCredits }
Run     { startedAt, totalMs, laps:[{courseId, ms, result}], mistakes, credits, ok }
```

`localStorage` 키: `drdrill.courses`, `drdrill.config`, `drdrill.runs`(최근 20건), `drdrill.version`.

## 5. 구현 계획 (순서와 이유)

1. **HANDOFF.md 작성** ← 규칙 6에 따라 코드보다 먼저. (완료)
2. **UI 스타일 후보 3종 HTML 작성 후 사용자 선택** ← 규칙 2-1. 본 구현 전에 반드시 통과.
   - A. 실전 클론(관공서풍 파란 헤더 + 회색 테이블): 실전 근육기억 전이가 최대
   - B. 아케이드 스피드런(다크 + 큰 타이머 + 랩타임): 반복 동기부여가 최대
   - C. 미니멀 트레이너(밝고 여백 큰 타이포): 정보 파악 속도가 최대
3. **`app.html` 구현** — 선택된 스타일로. 순서: 상태/저장소 → 준비화면 → 엔진(타이머·지연·판정)
   → 훈련화면 → 결과화면 → 업데이트 모듈.
4. **아이콘 생성**(스톱워치+체크, SVG→PNG→ICO) 및 **바로가기 3종**.
5. **`version.json`, `README.md`, 배포용 zip(`dist/`)**.
6. **보안 점검 후 보고**, 커밋 & 푸시(사용자 확인 후 릴리즈).

### 주요 설계 결정과 이유

- **단일 파일 앱**: `file://` 더블클릭 구동 요구 때문. 외부 리소스 0개 → 오프라인·영구 동작 보장.
- **행 순서 셔플**: 고정 배치면 좌표 암기가 되어 훈련 효과가 사라진다. 실제로는 매번 목록이 다르다.
- **실패를 확률적으로 섞음**: 실전에서 진짜 병목은 타자 속도가 아니라 *실패 후 대체 과목 전환 판단*이다.
- **결과 화면에 히스토리 병합**: 별도 기록 페이지는 중복 기능이라 통합(요구사항 2-0).
- **면책 배너 상시 노출**: 이 앱이 실제 서버와 무관한 오프라인 연습 도구임을 화면에 명시한다.

## 6. 제약 조건

- **네트워크**: GitHub 공개 API/raw 외 어떤 외부 요청도 금지. 특히 대학 서버 요청 절대 금지(2-0 참조).
- **구동**: 로컬 서버 금지. `file://` 더블클릭으로 동작해야 하며 CDN·외부 폰트 사용 금지.
- **개인정보**: 학번·비밀번호·이름을 입력받거나 저장하지 않는다. 과목 코드는 사용자가 임의로 넣는
  연습용 문자열이며 로컬에만 저장된다. 배포 zip에 개인 데이터·경로가 들어가지 않게 한다.
- **자격증명**: 토큰 하드코딩 금지.
- **업데이트**: 브라우저는 로컬 파일을 덮어쓸 수 없다 → "다운로드 후 교체" 방식으로 정직하게 구현.
- **저장소**: 루트의 철봉.com 파일들을 수정하지 않는다.
- **브랜치**: `claude/digest-course-registration-macro-i9o2bz` 에만 푸시한다.

## 7. 알려진 한계

- 실제 DGIST 사이트의 화면·API를 복제한 것이 아니다. 한국 대학 수강신청의 **일반적 절차**를
  재현한 것이라 실제 화면 배치와는 다르다. (의도된 설계다. 실제 사이트 모사는 2-0의 금지 사항과 맞닿는다.)
- 훈련은 손동작·판단 속도를 다듬을 뿐이며, 서버 경쟁 결과를 보장하지 않는다.
