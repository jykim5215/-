# 내 물가 (My CPI)

국가데이터처가 이미 계산해 둔 **품목별 소비자물가지수를 그대로 쓰고 가중치만
사용자 것으로 교체**해서 개인화된 물가상승률을 내고, 공식 지표와의 격차를
분류별로 분해해 보여주는 서비스.

원가격을 다시 구하지 않는다. 라스파이레스 산식에서 바뀌는 것은 가중치뿐이다.

```
공식지수  I_t = Σ(w_i × I_i,t) / Σw_i      (Σw_i = 1,000)
내 물가   P_t = Σ(v_i × I_i,t) / Σv_i      (v_i = 사용자 가중치)
전년동월비 rate = (P_t / P_{t-12} − 1) × 100
```

## 이 서비스가 말할 수 없는 것

읽고 시작해야 하는 부분이다. 이 목록은 기능 부족이 아니라 **데이터의 한계**다.

### 1. 이건 공식 물가가 아니다

공식 지수를 재가중한 **참고값**이다. 국가데이터처가 공표하는 소비자물가지수와
다른 숫자가 나오는 것이 정상이며, 그 차이가 이 서비스의 관심사다. 어떤 화면에서도
이 값을 공식 통계처럼 인용하면 안 된다. 결과 화면 상단에 이 문구를 상시 노출한다.

### 2. 카드 내역은 458개 품목으로 쪼개지지 않는다

카드 승인 데이터는 **가맹점 단위**이지 상품 단위가 아니다. 이마트에서 결제한
87,000원이 쌀인지 세제인지 옷인지 카드 데이터로는 알 수 없다. 그래서 이 서비스는
**12대 분류까지만 자동으로 나누고**, 그 아래는 사용자 입력에 맡긴다. 458개 품목
단위 자동 분류를 시도하지 않는다.

덧붙여 업종 → 12대 분류 대응에는 **공개 표준이 없다.** 카드사 업종 코드와
소비자물가지수 지출목적별 분류의 대응 관계는 공표된 적이 없다. 이 저장소의
매핑표(`app/mapping/mcc.py`)는 추정이며, 항목별 신뢰도를 함께 표시하고
사용자가 고칠 수 있게 했다. 수정 이력은 저장해 매핑 개선에 쓴다.

### 3. 2026년 12월 기준개편으로 과거 계산값이 바뀔 수 있다

2026-12-31 공표분부터 **2025년 기준(2025=100)** 으로 전면 개편된다.

- 품목 458 → 455개 (신규 10 / 제외 13)
- 가중치 전면 교체
- 2025년 1월 ~ 2026년 11월 지수가 **소급 재계산**

즉 오늘 본 "2026년 3월의 내 물가"가 개편 후에 다른 숫자가 될 수 있다. 이건 버그가
아니라 통계 개편이다. 그래서 이 서비스는 **계산 결과를 저장하지 않고 입력(사용자
가중치)만 저장한다.** 지수는 언제든 다시 당겨 재계산한다.

기준연도가 다른 지수가 한 계산에 섞이면 조용히 계산되지 않고 `BaseYearMismatchError`
로 즉시 실패한다.

### 4. 자가주거비는 헤드라인 CPI에서 빠져 있다

한국의 헤드라인 소비자물가지수는 **자가주거비를 포함하지 않는다**(주거 가중치 약
9.8%). 자기 집에 사는 사람의 체감 물가와 공식 지표가 가장 크게 어긋나는 지점이
여기다. 집값이나 자가주거비가 아무리 올라도 헤드라인 CPI는 그것을 거의 담지 않는다.

별도로 공표되는 **「자가주거비포함지수」** 를 옵션으로 제공한다. L0에서 주거형태를
'자가'로 고르면 이 한계를 안내한다.

### 5. 비슷한 서비스가 이미 있다

KOSIS 「나의 물가 체험하기」가 **2016년부터** 유사 기능을 제공하고 있다. 12대 분류
가중치를 직접 조정해 개인 물가를 계산해 볼 수 있다.

이 서비스의 차별점은 셋이다.

1. **실제 소비 데이터 기반 가중치** — 슬라이더를 손으로 옮기는 대신 카드 이용내역
   엑셀에서 실제 지출 구성을 뽑는다.
2. **기여도 분해** — 격차가 얼마인지가 아니라 *어느 분류가 그 격차를 만들었는지*를
   보여준다. 합이 격차와 정확히 일치하는 분해다.
3. **시계열 누적** — 한 달 스냅샷이 아니라 24개월 궤적으로 공식 지표와 나란히 본다.

## 시작하기

```bash
pip install -r requirements.txt
cp .env.example .env      # KOSIS_API_KEY 를 채운다
uvicorn app.main:app --reload
# http://127.0.0.1:8000
```

**KOSIS 인증키**는 [kosis.kr/openapi](https://kosis.kr/openapi) 에서 개인도 즉시
자동 발급된다. URL 인코딩된 형태(`%2B`, `%3D`)로 발급되어도 그대로 넣으면 된다.
클라이언트가 디코딩해서 보낸다.

키가 없으면 앱은 죽지 않고 모든 화면에 「데이터 없음(KOSIS 인증키 없음)」을
표시한다. **그럴듯한 값으로 채우지 않는다.**

### 선택 인증키

| 키 | 없으면 | 비고 |
|---|---|---|
| `KAMIS_CERT_KEY` + `KAMIS_CERT_ID` | ④ 장바구니만 비활성화 | 인증키와 계정 ID **두 개** 필요 |
| `OPINET_API_KEY` | ④ 장바구니만 비활성화 | 무료 키는 최근 7일만 제공 → 시계열은 일별 적재 필요 |

①②③ 화면은 KOSIS 키만 있으면 정상 동작한다.

## M0 인수 테스트

사용자 가중치 자리에 **공식 가중치를 그대로 넣으면 공표치가 재현되어야 한다.**

> 2026년 7월 = 전년비 **+2.8%**, 지수 **119.77** (2020=100)

```bash
pytest                          # M0는 픽스처가 없으면 사유를 붙여 SKIP
MYCPI_REQUIRE_M0=1 pytest       # M0를 하드 게이트로 (픽스처 없으면 FAIL)
```

이 테스트는 **실제 공표치 픽스처를 읽는다.** 지어낸 값으로 초록불을 만들지 않는다.
픽스처를 채우는 방법은 두 가지다.

```bash
# (a) 인증키와 네트워크가 되는 곳에서
export KOSIS_API_KEY=...
python scripts/fetch_m0_fixture.py --period 202607

# (b) 손으로 — tests/fixtures/official/README.md 의 형식대로
#     2026년 7월과 2025년 7월의 12대 분류 지수를 옮겨 적는다
```

**허용오차 ±0.05.** 공표 분류지수와 가중치가 이미 반올림된 값이라, 12분류 재집계는
원리상 0.01~0.02 수준의 오차를 남긴다. 스펙이 요구한 "소수점 첫째 자리 일치"와 같은
수준이다. 458품목 가중치를 적재하면 더 좁힐 수 있다.

데이터에 의존하지 않는 항등식(집계의 기본 성질, Σ기여도 ≡ 상승률, Σ격차기여 ≡ 격차,
기준연도 혼입 시 예외)은 픽스처 없이도 항상 검증된다.

## 가중치 정하는 3단계

| 단계 | 무엇 | 비고 |
|---|---|---|
| **L0** | 가구원수 / 소득분위 / 주거형태 / 자차유무 4문항 | 30초, 가입 없음. 업로드 없이도 결과가 나온다 |
| **L1** | 12대 분류 슬라이더 직접 조정 | 합계 1,000 자동 정규화, 즉시 재계산 |
| **L2** | 카드 이용내역 엑셀 업로드 | 신한·KB·삼성·롯데 |

**마이데이터·오픈뱅킹 연동은 구현하지 않는다.** 본인신용정보관리업은 법인 + 자본금
5억 + 금융위 허가가, 오픈뱅킹은 법인 + 전자금융업 등록 + 보안점검이 필요해서
개인·소규모 사업자는 이용할 수 없다.

### L2의 개인정보 처리

**파일은 서버로 전송되지 않는다.** 카드 이용내역은 브라우저 안에서만 파싱되고,
서버로 가는 것은 집계된 **12개 분류 가중치 숫자뿐**이다. 가맹점명·결제일자·금액은
전송되지 않는다. 이 사실을 업로드 화면에도 명시했다.

### L0의 한계

주거형태와 자차 유무는 12대 분류 구성비만으로는 반영할 수 없다(자가주거비는 헤드라인
CPI에서 제외돼 있고, 자차 유무는 교통 분류 *안에서* 운영비 품목이 갈리는 문제라 품목
단위 가중치가 있어야 한다). 그래서 **조정 계수를 지어내지 않고** 해당 분류에 확인
힌트를 붙여 L1 슬라이더로 유도한다. 품목 가중치 엑셀이 적재되면 이 자리에서 재배분할
수 있다.

가계동향조사 구성비 조회에 실패하면 공식 평균 가중치로 내려가되, **"아직 개인화되지
않았다"는 사실을 화면에 그대로 알린다.**

app/weights/segments.py    소득분위별 기본 가중치

### 숫자를 지어내지 않기 위한 장치

원칙을 주석이 아니라 구조로 만들었다.

- **`Measured` / `Unavailable`** — 앱 밖으로 나가는 수치는 반드시 출처가 붙은 값이거나
  사유가 붙은 부재다. 출처 없는 raw float가 화면에 도달할 경로가 없다.
- **기준연도를 응답에서 읽는다** — 단위명 `2020=100` 을 파싱한다. 상수로 가정하지
  않으므로 2025=100 개편 후에도 코드를 고칠 필요가 없다.
- **결측은 0이 아니라 `None`** — KOSIS의 `-`, 빈 값, `X` 를 0으로 바꾸면 지수가
  조용히 왜곡된다.
- **분류가 빠지면 계산 거부** — 가중치가 있는 분류의 지수가 없으면 그 분류를 빼고
  계산하지 않는다. 분모가 달라져 결과가 왜곡되기 때문이다.
- **픽스처 분리** — `tests/fixtures/protocol/` 은 응답 *형태*만 담은 합성 데이터로
  화면에 도달할 경로가 없고, 실데이터는 `tests/fixtures/official/` 에만 둔다.
  후자는 출처 필드가 없으면 테스트가 실패한다.

### KOSIS 클라이언트가 막는 것들

| 실수 | 어떻게 막았나 |
|---|---|
| 기간 파라미터 두 세트 동시 전송 | `PeriodRange \| RecentCount` union — 함께 보내는 코드를 쓸 수 없다 |
| 오류 응답을 정상으로 처리 | 배열/객체를 `isinstance` 로 분기해 `KosisApiError` |
| `err=20` | `objL2` → `objL3` 순으로 `"ALL"` 채우며 최대 3회 재시도 |
| URL 인코딩된 인증키 | `%` 가 있으면 디코딩해서 전송 |
| `'+'` 가 공백으로 오독 | 다중값은 공백 결합 + `%20` 인코딩, 왕복 테스트로 고정 |
| 코드 추측 하드코딩 | `data_validated()` 가 `meta(type="ITM")` 를 먼저 부르고 검증 |
| 통계표 ID 하드코딩 | 목록 조회 → `search()` 재탐색 → 폴백 힌트(썼다는 사실을 출처에 남김) |
| 호출량 초과 | SQLite 6시간 TTL 캐시 + 호출 간 0.3초. 오류 응답은 캐시하지 않는다 |

## 화면

| | | |
|---|---|---|
| ① | **내 물가** | 큰 숫자 하나 + 공식 대비 격차 + 설명 한 문장 |
| ② | **왜** | 분류별 기여도 발산 막대. **내 물가를 낮춘 항목도 함께** 표시 |
| ③ | **궤적** | 공식 CPI vs 내 물가 24개월 |
| ④ | **장바구니** | 상위 분류의 최근 가격 (KAMIS·오피넷 키 필요) |

### ② 화면을 읽을 때 주의할 것

**기여도가 음수라고 해서 그 분류의 가격이 내린 것이 아니다.** 가격은 올랐지만 내 비중이
평균보다 낮아 덜 맞았을 뿐인 경우가 대부분이다. "물가를 끌어내린 게 교통"처럼 읽으면
사실과 반대가 된다.

그래서 문장 생성기는 세 부호를 **각각 따로** 판정한다.

1. 격차의 부호 → 내 물가가 공식보다 높은가 낮은가
2. 격차기여의 부호 → 그 분류가 내 몫을 더했는가 뺐는가
3. **분류 상승률의 부호 → 그 분류의 가격이 올랐는가 내렸는가**

3번을 1·2번으로 추론하지 않는다. 네 조합 전부에 테스트가 있다
(`tests/test_narrative.py`).

### 색 접근성

지정 팔레트를 검증한 결과 초록 `#3DD68C` 과 주황 `#FF9151` 이 적록색약(deuteranopia)
에서 ΔE 7.2로 구분이 약하다. 그래서 **색 외 단서를 항상 병기한다.**

- 모든 수치에 `+`/`−` 부호
- 발산 막대의 하락 항목에 빗금
- 범례 상시 노출
- 색을 쓰지 않는 **표 보기**

숫자는 `tabular-nums` 로 자리를 고정한다.

## 기여도 분해가 정확한 이유

직관식 `(내비중 − 평균비중) × 분류상승률` 은 두 분모(`P_{t-12}`, `O_{t-12}`)를 같다고
본 근사라서 합이 격차와 정확히 맞지 않는다. "격차를 분류별로 분해한다"가 참이려면 합이
맞아야 하므로 분모를 살린 정확식을 쓴다.

```
기여도_i    = 비중_i × (I_i,t − I_i,t-12) / P_{t-12} × 100
Σ기여도_i   ≡ 내 물가 상승률

격차기여_i  = 내비중_i × ΔI_i / P_{t-12} × 100 − 평균비중_i × ΔI_i / O_{t-12} × 100
Σ격차기여_i ≡ 내 물가 상승률 − 공식 상승률
```

두 항등식 모두 테스트로 못 박았다. 분모가 같으면 직관식으로 환원된다.

## 배포와 업데이트

```bash
python scripts/package_release.py              # 보안 점검 + dist/mycpi-<version>.zip
python scripts/package_release.py --check-only  # 점검만
```

점검 항목: 개인정보·로컬 산출물(.env, *.sqlite3) 포함 여부, 하드코딩된 자격증명,
`.gitignore` 의 `.env` 보호, 공식 픽스처의 출처 표기. 하나라도 걸리면 zip 을 만들지
않고 종료 코드 1을 돌려준다.

앱 안의 **업데이트 확인** 버튼이 `version.json` 의 `repository` 로
GitHub Releases API를 조회해 새 버전을 알린다. 공개 저장소의 공개 API만 쓰므로
토큰이 필요 없고, 코드에 자격증명을 담지 않는다. 확인에 실패해도 앱 사용은 막히지
않는다.
